# Damage stays local; audits tolerate what mutators refuse

Governs `src/ops/check/`, `src/ops/verify.rs`, `src/repo/blobs/`, `src/repo/lock*.rs`, `src/repo/snapshots.rs`, `src/damage.rs`, `src/output.rs`.

**Damage locality.** A corrupt pack header or cached descriptor must not hide blobs that are independently indexed and authenticated. Check keeps indexed descriptors when headers are damaged, verify reads indexed blobs of a pack whose header is corrupt, and the tree reader records header damage but still verifies the tree. A valid header is authoritative: a bad cached descriptor is index damage, not proof that the stored blob is corrupt. A swapped pack has an authentic header under the wrong name; a structural check reads a pack in full only when the name does not match. Readers try every copy of a blob, but scan alternatives only once, and only when a referenced primary pack disappeared during a concurrent repack. Verify's any-good-copy rule is separate from that general reader fallback.

**Damage oracle.** The damage harness builds its expected set from the intact graph, never from audit output, and compares (object, kind, problem), not only object IDs. Each injection is built so one detector is the only signal: authenticated injections re-seal valid AEAD so only keyed-ID, framing or cache checks can catch them, and renaming the pack after a swap removes whole-pack hashing as a competing detector. It forces a mixed data/tree pack so backup scheduling cannot change the expected set. The oracle rules are in `tests/damage_support/byte_cases.rs` (body flips are undecryptable blobs, invalid metadata ciphertext is a hash mismatch except for config, truncated envelopes are bad-format, unreadable roots and indexes hide their descendants and nothing below them is guessed).

**Locks.** Audits still report malformed locks while honouring every readable live lock; mutating operations refuse malformed locks. A lock may disappear between list and read during refresh or release; that is not damage. A stalled process must not resurrect its lock after another operation has treated it as stale. PID liveness: EPERM means the process exists; only ESRCH proves it is gone. The `*_without_lock` read functions behind `--no-lock` require the caller to exclude concurrent writers.

**Newest snapshot.** Backend modification times only order the reads; the authenticated snapshot time decides which snapshot is newest, so every candidate is read.

**Output.** Damage JSON identifies files by their raw POSIX path bytes (base64), so non-UTF-8 names stay exact. One index payload stays below the envelope's 64 MiB decompression cap (flush at 32 MiB). `io::Error` and `serde_json` forward `source()` past their own wrappers, so the stdout-closed marker sits one level down, where repository wrappers also preserve it and broken pipes keep exit 0.
